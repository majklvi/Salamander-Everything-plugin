# Querying Everything from a Samandarin panel

## Backend choice

Use the Unicode interface of **Everything SDK v2** for the first version. It supports asynchronous queries against full Everything 1.4.1 and works with compatible 1.5 instances. It gives the plugin filenames, parents, types and result counts without enumerating the filesystem. Pass the text through as an Everything query so inputs such as `ext:pdf invoice` and `folder: reports` keep their familiar meaning. Search scope is the set of locations indexed by the user's Everything instance. [SDK overview](https://www.voidtools.com/support/everything/sdk/) · [SDK generations and compatibility](https://github.com/voidtools/everything_sdk3#download) · [Search syntax](https://www.voidtools.com/support/everything/searching/)

| API | How it returns results | Fit |
| --- | --- | --- |
| SDK v2, full Everything 1.4.1 and compatible 1.5 | Window-message IPC. `Everything_QueryW(FALSE)` sends a query and delivers the answer to a reply window. | Recommended for live typing on the default instance. One owner should coordinate the SDK's query settings and result list across tabs. [Query](https://www.voidtools.com/support/everything/sdk/everything_query/) · [Reply handling](https://www.voidtools.com/support/everything/sdk/everything_isqueryreply/) |
| SDK v3, Everything 1.5 | Named pipe with an explicit client, search state and result list. `Everything3_Search` blocks, so it belongs on a worker. | Prefer this if selecting named 1.5 instances or watching an already displayed query for index changes becomes a requirement. Shutting down a client cancels all its pending requests. Independent searches need separate clients if they must be cancelled independently. [SDK v3](https://github.com/voidtools/everything_sdk3) · [Author's API reference](https://www.voidtools.com/forum/viewtopic.php?t=15853#api) |

The full Everything search application must be running in the user's session. The Windows service supplies indexing access to the application. The Lite edition omits the IPC used by v2. For distribution, the plugin can ship a matching-architecture client library or build the SDK into the plugin, retaining the SDK license notice. Everything itself remains a separate user installation. A scripted Salamatrix variant could call the same client DLL from a runtime such as CPython. The DLL must then match the worker process. [Everything Service](https://www.voidtools.com/support/everything/everything_service/) · [Edition comparison](https://www.voidtools.com/en-us/faq/) · [SDK license clarification](https://www.voidtools.com/forum/viewtopic.php?t=6687) · [Official Python example](https://www.voidtools.com/support/everything/sdk/python/)

## From one keystroke to the correct rows

1. **Track the search per tab.** Each edit advances the query generation, including clearing the field. An empty field can show an invitation to type. Coalesce rapid edits, starting with 100 ms for measurement. A new v2 request can supersede an earlier one. The plugin should therefore serialize requests across tabs, keeping the newest pending query for each tab. A worker with a message loop can own this queue so a slow query leaves the editor responsive. [Author's explanation of concurrent queries](https://www.voidtools.com/forum/viewtopic.php?t=8282)
2. **Send a bounded request.** Set the search text, ordering, requested fields, reply window and unique reply ID before `Everything_QueryW(FALSE)`. A first page of 200 items is a proposed starting point. Use `Everything_SetMax` and `Everything_SetOffset` to page, `Everything_GetNumResults` for the page size and `Everything_GetTotResults` for the overall count. Show “200 of 18,430” when appropriate. If sorting a partial listing by a new column, request page one in that order from Everything. [Query settings](https://www.voidtools.com/support/everything/sdk/everything_query/) · [Request IDs](https://www.voidtools.com/support/everything/sdk/everything_setreplyid/) · [Total count](https://www.voidtools.com/support/everything/sdk/everything_gettotresults/)
3. **Associate the reply with its owner.** Let a plugin-owned message loop receive `WM_COPYDATA` and validate the expected ID through `Everything_IsQueryReply`. Copy the returned data into an owned snapshot before reusing the SDK state. Hand the snapshot to the host UI only if both the original tab and its generation still match. A closed or reused tab drops the reply. Clearing the field invalidates in-flight replies immediately. This remains correct even if Everything finishes an older search. [Asynchronous reply contract](https://www.voidtools.com/support/everything/sdk/everything_isqueryreply/)
4. **Show names, act on full paths.** Keep the exact UTF-16 full path and file/folder type of each hit. Display the basename and parent separately. Size and modification time are optional and depend on available result fields. Read the actual returned flags and use a path buffer large enough for the entire name. On refresh, preserve focus and selection only for identities still present. Apply updates without taking focus from the editor. [Result fields](https://www.voidtools.com/support/everything/sdk/everything_setrequestflags/) · [Returned flags](https://www.voidtools.com/support/everything/sdk/everything_getresultlistrequestflags/) · [Full paths](https://www.voidtools.com/support/everything/sdk/everything_getresultfullpathname/)

A search result is a snapshot of the index. A file can be renamed after delivery, offsets can shift between page requests, and a disconnected share can still have matching entries. Avoid per-row disk or network probes while painting. Attempt the chosen operation on its recorded target and surface a failure for that row. Distinguish “No matches” from “Everything is unavailable” and “Everything is loading its index.” The v2 `Everything_IsDBLoaded` and `Everything_GetLastError` functions distinguish loading from IPC failure. A manual refresh can rerun the current text after recovery. [Folder indexing and offline volumes](https://www.voidtools.com/support/everything/folder_indexing/) · [Database readiness](https://www.voidtools.com/support/everything/sdk/everything_isdbloaded/)

## What a prototype should verify

| Scenario | Observable success |
| --- | --- |
| Type, paste, erase and retype while a broad query is still running. Search in the other panel, then close or detach the first tab. | Only the latest text for each surviving tab supplies its rows. Focus stays with the user. A late reply cannot populate a different tab. |
| Several drives contain `report.pdf`. Change the sort, refresh, and open one copy. Include a directory hit, Unicode names, a path beyond 260 characters and an indexed UNC location. | The parent column distinguishes all copies. Enter opens the intended file or directory. “Open containing folder” focuses the exact file in its real parent. No truncation or selection transfer to a namesake. |
| Search a large index with a broad expression, then narrow it while the first page is being prepared. | Record the time from the last edit to the first usable rows, including debounce, IPC and host refresh. Compare first-open and warm searches. The result count is accurate and scrolling and typing stay responsive. |
| Stop or restart Everything, try a loading index, remove a matched file, or disconnect a matched share. | The panel distinguishes the failure from a valid empty result, remains usable, and can rerun the current search. An action on a missing target reports that target. |

These are proposed checks. The review used published sources and contracts. It produced no runtime measurements.
